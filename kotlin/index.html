Kotlin, for reviewing
real-world code.

Built around the kind of code you'll actually review, explained in TypeScript terms, one small idea at a time.

The goal.

Read a Kotlin PR without slowing down to guess.

Mission

Review with confidence

For any line using ?., ?:, !!, let, apply or when, say what it does and what happens on null. Then leave the comment that catches misuse.

Format

Small and real

Five-minute lessons, each ending in a quiz. Analogies come from TypeScript. Every example looks like code you'll meet in a real backend.

Not now

Out of scope

Writing new Kotlin features, coroutines, DSL design and build tooling. They can wait until reading is easy.

Where Kotlin lives.

On a typical JVM backend, it shows up in a handful of recognisable shapes.

Kotlin only

Newer services

Small services written in Kotlin from day one. This is where the most idiomatic Kotlin lives, so most lesson examples look like this.

Mostly Java

Large legacy codebases

A few dozen Kotlin files among thousands of Java ones. It often reads like Java written in Kotlin, which makes it useful critique material.

Mostly Java

Shared event libraries

Small Kotlin data classes for events and messages. Many have return data!! in getData().

Java only

Everything else

No Kotlin at all.

Review is the style guide Plenty of teams never lint Kotlin. Then whatever Kotlin style a team has only holds if reviewers notice when it slips. That's why this course aims at reviewing.

What you'll see most.

Rough counts from a survey of a mid-sized Kotlin backend.

  • it, the implicit lambda parameter~460
  • ?:, Elvis, including ?: return and ?: throw~46
  • !!, mostly in tests and event classes~32
  • with(x) { … }, mostly in data ingestion code26
  • takeIf { … }17
  • ?.let { … }13
  • when, almost always as an expression~10
  • also, apply, run~20 combined

Null safety

?. and ?: work like TS. !! crashes at runtime, which TS's ! never does.

02

The two arrows

In { x -> … }, the arrow separates parameters from the body. In when, it means "this case gives this result".

03

?.let and it

"If it's there, transform it." Otherwise the whole expression is null.

Explained in chat
04

when as an expression

A switch that returns a value. It must cover every enum entry, and null too. Leaving out else is deliberate.

Explained in chat
05

Scope functions

let, also, apply, run and with differ in two ways: whether the object is it or this, and what comes back.

Explained in chat
06

this in lambdas

Ordinary lambdas behave like arrow functions. apply, run and with bind this to the object, like fn.call(obj).
