01

Null safety

Three operators. Two of them behave just like TypeScript; the third is a trap.

TypeScriptKotlinWhat happens on null
string | nullString?Plain String can never be null. The compiler enforces it.
a?.ba?.bReturns null instead of crashing. Same as TS.
a ?? ba ?: b"Elvis". Uses b only when a is null.
a!a!!Kotlin throws a NullPointerException. TS's ! does nothing at runtime.
The trap for TS developers In TypeScript, x! is a promise to the compiler that gets erased from the output (TS handbook). In Kotlin, x!! is a runtime check that crashes with an NPE when x is null (Kotlin docs). In review, every !! deserves the question "what guarantees this isn't null?"

Kotlin can do something TS can't

return and throw are expressions in Kotlin, so they can sit on the right side of ?: (docs). This is the idiomatic guard clause. It also leaves you with a non-null variable.

val title = Titles.normalize(request.title) ?: throw IllegalArgumentException("title must not be blank")
// title is String here, not String?
val customer = customerRepository.findCustomer(order.customerId) ?: return null

02

Lambdas and the two arrows

-> means two different things depending on where it appears.

Inside { }, the arrow separates parameters from the body

TypeScript
items.map((x) => x * 2)
// no TS equivalent of `it`
Kotlin
items.map { x -> x * 2 }
items.map { it * 2 }

Kotlin lambdas live entirely inside the braces. If a lambda has exactly one parameter, you can skip naming it, and it's called it (docs). When the lambda is the last argument, it moves outside the parentheses, which is why you see map { … } instead of map({ … }) (docs).

Inside when, the arrow means "this case gives this result"

TypeScript
switch (status) {
  case "PENDING": return a;
  case "SHIPPED": return b;
}
Kotlin
when (status) {
  PENDING -> a
  SHIPPED -> b
}

03

?.let: do this only if it's there

The most common way Kotlin code transforms a value that might be null.

shipment?.let { ShipmentDTO(it.carrier, it.shippedAt, it.trackingCode, it.note) }

Read it in two halves. ?. says "if shipment is null, stop here and give back null". let { … } says "otherwise, run this lambda with shipment as it, and give back whatever the lambda returns". The TS equivalent:

shipment == null ? null : toDto(shipment)

Another example of the same pattern:

store?.let { Currency.fromCodeOrNull(it.settings.currencyCode) }
// Currency? — null if store is null OR the currency code is unknown

04

when as an expression

A switch that returns a value, and refuses to compile if you forget a case.

private fun reminderDelayOf(status: OrderStatus) = when (status) {
    OrderStatus.PENDING -> properties.pendingReminderAfter
    OrderStatus.SHIPPED -> properties.deliveryReminderAfter
}

When when produces a value, the compiler requires every possible value of the subject to be covered (docs). For an enum, that means every entry. For a nullable enum, it also means null. Commas group several cases: Region.EU, Region.UK, null -> false.

TypeScript gets the same safety only if you add a never check in the default branch. In Kotlin, it comes free, as long as nobody writes else.

Review lens No else on an enum when is deliberate. Adding Region.APAC later breaks the build, which forces whoever adds it to decide what Asia-Pacific shows. An else -> false would silently say "no". If a PR adds an else to an enum when, ask why.

05

Scope functions

Five functions that run a block of code against one object. They differ in only two ways.

FunctionThe object is calledReturnsReach for it to…
letitlambda resulttransform a value, usually after ?.
alsoitthe objectadd a side effect like logging or storing (TS: a "tap")
applythisthe objectconfigure an object you just created
runthislambda resultconfigure, then compute a result
with(x)thislambda resultmake several calls on x

Source: the selection table in the official scope functions docs.

apply · configure and return the object

fun storefrontETags() = FilterRegistrationBean(ShallowEtagHeaderFilter()).apply {
    addUrlPatterns("/shop/", "/shop/index.html", "/shop/app.js", "/shop/app.css")
}

also · keep the value, do something on the side

val batch = pending ?: orderRepository.newBatch(type).also { pending = it }

with · many calls on one object

private fun ReceiptDeliveryFailedEvent.isBounceWeRetry() = with(data) {
    category == "Bounce" && RETRIED_CHANNELS.any { channel.equals(it, ignoreCase = true) }
}

Inside the block, category means data.category.

06

What this means inside a lambda

If you know JavaScript's this rules, you already know this.

KotlinBehaves like (JS/TS)this is…
ordinary lambda: let, also, mapan arrow functionwhatever it was outside, usually the enclosing class
lambda with receiver: apply, run, withfn.call(obj), or a function with a this: T parameterthe object

The difference shows up in the types. (T) -> R takes the object as a parameter, and you get it. T.() -> R runs as if it were a method on T, so you get this (docs). In TS terms, T.() -> R is (this: T) => R.

Inside a receiver lambda, bare names resolve to the object first. If you need the outer class, label it: this@OrderController. That's also why let often reads better in review: with it, you always know where a name comes from.
